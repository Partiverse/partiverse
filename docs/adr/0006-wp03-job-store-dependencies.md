# ADR-0006 WP03 JobManager 依赖集(rusqlite bundled + serde_json;job 落库)

- 状态: 接受 | 日期: 2026-10-09 | 负责人: @partiverse
- 背景: M1-WP03-T02(JobManager:job 状态机+启动对账+SQLite 落库)需要 SQLite 持久化(jobs 表 v1+最小迁移框架)与 rc 载荷参数面。任务卡候选:rusqlite(bundled),禁选 sqlx/tokio/governor 等候选外重依赖;deny.toml 约束与 ADR-0004/0005 同款(`multiple-versions="deny"`、`wildcards="deny"`、license 白名单禁改,本 ADR 不改 deny.toml)。铁律 8:新依赖需 ADR;license 审计读 registry 内 Cargo.toml 实测(非记忆)。
- 决策: partiverse-core 新增 2 个直接依赖(版本为 2026-10-09 rsproxy 解析最新):
  1. `rusqlite 0.40.2`(**license=MIT**,实测其 registry Cargo.toml 第 41 行——审查 [low] 修正,原记 33 行系 libsqlite3-sys 的)——job 落库;`default-features = false` + `features = ["bundled"]`(自带编译 SQLite amalgamation,免系统 libsqlite3 耦合;bundled 隐含 `modern_sqlite`)。**默认特性实测裁剪**:上游 default=`["cache", "ffi-sqlite-wasm-rs"]`,其中 `ffi-sqlite-wasm-rs` 为 wasm32 目标拉入 `sqlite-wasm-rs 0.5.5 → rsqlite-vfs 0.1.1 → hashbrown 0.16.1`,与树内 hashbrown 0.17.1(hashlink/indexmap)构成跨目标双版本——cargo-deny 未配 `targets` 时按全目标图检查,实测 bans 节红(`duplicate: found 2 duplicate entries for crate 'hashbrown'`),裁剪后 `cargo tree --workspace --target all --duplicate` 零重复;`cache`(→hashlink)本卡无使用面一并关闭。本卡 API 用面仅核心(Connection/execute/query_row/params!/OptionalExtension/unchecked_transaction/busy_timeout),无 cache/hashlink 依赖;
  2. `serde_json 1.0.151`(**MIT OR Apache-2.0**)——rc 载荷参数面(`RcDispatch::call` 出入参、`_async:true` 注入);与 partiverse-engine 同版本单源,零新增树内包。
  **内部依赖(结构裁定,须 Owner 知会)**:任务卡授权「core 新增 partiverse-engine path 依赖(向下依赖)」,但 Cargo 禁止普通依赖成环(partiverse-engine 已依赖 partiverse-core,普通依赖将构成 `partiverse-core → partiverse-engine → partiverse-core` 环,cargo 拒绝解析),故落为 **`[dev-dependencies] partiverse-engine = { path = "../partiverse-engine", version = "0.1.0" }`**(仅集成测试消费;显式 version 避免 wildcards=deny 误伤,ADR-0004 同款)。生产消费面 = core 内 `jobs::RcDispatch` trait(severity 经 PartisyError 保真上浮),T01 `RcClient` 适配器由引擎/应用层提供——本卡集成测试 `tests/jobs_real_engine.rs::RcAdapter` 即该适配的首个形态证明(白名单 `RcMethod::try_from_name` 收口 + severity 保真映射),后续 WP06/app 接线直接复用此形态。
- 理由: ①license 实测(逐个读 registry 内 Cargo.toml `[package].license`,非记忆):rusqlite 0.40.2=MIT;**libsqlite3-sys 0.38.2=MIT**(注:任务卡预飞须知按 partisync 同件先例记录为「MIT OR Apache-2.0」,系旧版口径,0.38.2 实测单表达式 MIT,均在白名单内,以实测为准);bitflags 2.13.2/smallvec 1.16.2/hashbrown 0.17.1/cc 1.6.0=MIT OR Apache-2.0;foldhash 0.2.0=Zlib;fallible-iterator 0.3.0 与 fallible-streaming-iterator 0.1.9=`MIT/Apache-2.0`(SPARC 斜杠简写,deny licenses 节实测放行)。**零商业授权**(无付费许可/年费/审核费/主体证书要求),依铁律 8 无需更新 docs/07 审计表;bundled 的 SQLite amalgamation 为公有领域。②deny 四节实测绿(deny.toml 顶层检查组=licenses/bans/sources+advisories,审查 [low] 修正原「五节」口径):`cargo deny check` = advisories ok / bans ok / licenses ok / sources ok(advisories 经代理 127.0.0.1:7897 取库;两条 license-not-encountered warning 为仓内预存基线,与本卡无关)。③候选池外未采用:sqlx(禁选;且引 tokio 运行时)、tokio(本卡 API 同步阻塞,ADR-0004 惯例调用方 spawn_blocking)、governor(限流属 T03 预算器)、dirs(目录解析 core 内自实现约 25 行 std,ADR-0004 同款口径——其 windows-sys 链与 ring 必然错开)、uuid/ rand(jobs.id 以「unix 毫秒时间戳前缀+std RandomState 熵种 SipHash 随机后缀」自实现,uuid v7 意图的时间有序性保留,零依赖)。
- 影响: 正向=job 状态机/对账/落库以最小依赖落地,host 树净增 7 包(rusqlite、libsqlite3-sys、fallible-iterator、fallible-streaming-iterator、smallvec、pkg-config、vcpkg;bitflags/cc/hashbrown/foldhash 树内已有——审查 [low] 修正原「6 包含 bitflags」清点失实)+复用 serde_json,全目标零重复版本、license 全白名单;代价=①bundled 需 CI 具 C 编译器(cc 1.6.0 编译 SQLite amalgamation,构建时间+数秒),SQLite 版本随 libsqlite3-sys 升级;②`platform_data_dir` 为 core 内第二份同语义实现(与 engine installer 各持一份,故意不跨 crate 复用以维持零环;engine 侧有单测锚定,core 侧零独立单测、经集成测试间接行使——审查 [medium] 修正原「两份均有单测锚定」失实,补强任务已登记);③核心错误经 `RcDispatch` 接缝后结构化 kind 位于 source 链(顶层仅 severity+Display),T03 预算器如需 `RcThrottled` 结构化识别须在引擎层做(matches! 于 EngineError)再喂 JobManager。生产代码零 unsafe(core 侧目录解析与 engine 同语义,行为锚定在 engine installer 单测,core 侧经集成测试间接行使)。波及面=WP06 任务队列、WP05 UI 任务面板直接消费 `JobManager`/`JobRecord` 及 `poll` 返回 `(JobRecord, Option<Value>)` 同步 API(审查 [low] 修正原引不存在的 `PollOutcome` 类型名)。
