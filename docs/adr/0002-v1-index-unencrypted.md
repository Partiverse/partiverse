# ADR-0002 V1 索引不加密

- 状态: 接受(Owner 已批准 ✅Q3) | 日期: 2026-10-09 | 负责人: @partiverse
- 背景: SPEC WP08 将建 SQLite+FTS5 统一索引(文件名/路径/元数据,落用户设备)。产品红线 4 要求「凭据与索引只存用户设备」,凭据侧已有强制加密方案(OS keychain / rclone 加密 config,WP04);索引侧是否额外做静态加密(透明加密层)为 Q3 提出项,Owner 已裁决:V1 不加密。本 ADR 记录该决策及其边界。
- 决策: V1 的 SQLite+FTS5 索引以明文 SQLite 落盘于应用数据目录,不引入静态加密层;本决策不触碰凭据安全边界(凭据仍按红线 4 强制入 OS 凭据库或 rclone 加密 config,禁止明文落盘)。
- 理由: ①索引内容按红线 3 仅含文件名/路径/元数据,不含用户文件内容、更不含凭据,敏感度显著低于凭据侧;②主流操作系统已默认设备级全盘加密(BitLocker/FileVault/LUKS),提供静态数据基础防线;③SQLCipher 类方案属新依赖(铁律 8 需另立 ADR)且对 FTS5 全文检索有性能与兼容成本,与 WP08「FTS5 名称搜索 P95<300ms」预算冲突。被否选项:SQLCipher/自研页加密——防「物理接触设备的攻击者读取元数据」的增量收益,不足以抵偿依赖与性能成本,推迟至出现明确用户需求再评估。
- 影响: 正向=索引栈零额外依赖、FTS5 全速运行、WP08 实现面最小;代价=能物理接触设备者可读取索引元数据(风险已登记,V1 接受);波及面=WP08 索引 schema 与存储路径;V2 若转加密需数据迁移与密钥管理方案,另立 ADR。
