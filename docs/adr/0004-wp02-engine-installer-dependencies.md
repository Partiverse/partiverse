# ADR-0004 WP02 引擎分发器依赖集(ureq/zip/sha2/hex/serde/serde_json)

- 状态: 接受 | 日期: 2026-10-09 | 负责人: @partiverse
- 背景: M1-WP02-T01(引擎分发器)需要 HTTP 下载、sha256 校验、zip 解包、manifest 反序列化与目录解析能力。任务卡候选池建议 tokio/serde/serde_json/sha2/hex/zip/dirs/ureq/rand|getrandom,并要求逐个 license 审计 + 商业授权核查 + deny 五节绿;铁律 8 要求新依赖需 ADR。仓库 deny.toml 现行门禁:`multiple-versions = "deny"`、`wildcards = "deny"`、license 白名单仅 MIT/Apache-2.0/BSD/ISC/Unicode/CDLA/Zlib,且白名单修改属作业红线(需另行 ADR),本 ADR 不改 deny.toml。
- 决策: partiverse-engine 引入 6 个第三方依赖(选自候选池,版本为本日 rsproxy 解析最新):
  1. `ureq 3.4.2`(MIT OR Apache-2.0)——多源下载的同步 HTTP 客户端;默认特性 rustls+gzip,ring 为 TLS provider,证书校验强制、任何代码路径无关闭开关;阻塞调用由调用方(async 集成层)放 spawn_blocking,本 crate 公共 API 保持同步;
  2. `zip 9.0.0`(MIT)——zip 解包;`default-features = false` + `deflate-flate2-zlib-rs`(纯 Rust 解压后端),关闭 aes-crypto/bzip2/deflate64/lzma/ppmd/time/zstd 等读取 rclone 发行包用不到的特性,依赖树由 40+ 枝收敛至 5 项(flate2/crc32fast/indexmap/memchr/typed-path);
  3. `sha2 0.11.0`(MIT OR Apache-2.0)——下载 zip 与落盘二进制的 sha256 完整性校验(RustCrypto);
  4. `hex 0.4.3`(MIT OR Apache-2.0)——摘要 hex 编解码(manifest 值比对/留档);
  5. `serde 1.0.229` + `serde_json 1.0.151`(均 MIT OR Apache-2.0)——engine-manifest.json 反序列化(含 `deny_unknown_fields` 严格模式)。
  **候选池内未采用**:tokio(T01 无异步面;同步 API + 调用方 spawn_blocking 已满足卡内「阻塞调用放 spawn_blocking」语义,避免为包装而引重型运行时,T02 rcd spawn 需要时再按程序立卡)、rand/getrandom(无随机性需求;ureq→ring 自带的 getrandom 0.2 为其内部传递依赖,非直接依赖)。**候选池外替代**:dirs(7.0.0)——实测弃用,见下方理由;安装根解析以 crate 内 `installer.rs` 内联函数 `platform_data_dir()`(约 25 行 std 实现,linux=XDG_DATA_HOME→~/.local/share、macOS=~/Library/Application Support、windows=%LOCALAPPDATA%,行为逐条对齐任务卡 ⑤)替代。内部依赖 `partiverse-core`(path,显式 version="0.1.0",AGPL-3.0)用于 Severity 错误分级。
- 理由: ①license 审计(cargo metadata 实测解析版本,非记忆):全部 MIT / MIT OR Apache-2.0,**零商业授权**(无付费许可/年费/审核费/主体证书要求),依铁律 8 无需更新 docs/07 审计表、无需备选方案;deny licenses 节绿。②`deny multiple-versions = "deny"` 是硬约束:实测 dirs 7→dirs-sys 0.5→windows-sys >=0.59(解析 0.61.2),而 ureq→rustls→ring 0.17 钉 windows-sys 0.52,双版本必红;回退 dirs 6/5 亦分别绑定 0.59+/0.48,任何 dirs 版本都与 ring 错开——deny.toml 白名单禁改,故自实现是唯一不触红线路径。③zip 特性裁剪同理:默认特性会同时拉入 getrandom 0.4(与 ring 的 0.2 重复)、zstd-sys(C 构建)、time 等,裁剪后 `cargo tree --target all` 零重复版本,deny bans 节绿。④ureq 相对候选池内唯一异步选项 tokio+reqwest 树小一个数量级,且任务卡明示推荐。被否选项:改 deny.toml 为 windows-sys 加 skip(触作业红线,否决);换 native-tls 后端(引 openssl-sys 系统依赖,CI 脆弱性上升,否决);调系统 unzip(卡内明令禁止,否决)。
- 影响: 正向=依赖树最小(直接 6 个+传递约 40 个,全白名单 license,单版本),CI 步骤 `cargo run -p partiverse-engine --bin engine-install` 在真实环境端到端验证下载/校验/落盘;代价=platform 目录解析自维护(XDG/已知目录语义变更时需跟进,行为有单测锚定)、zip 仅启用 deflate(未来若官方改压缩算法需扩特性,官方 zip 十余年恒为 deflate,风险低)、sidecar(`<binary>.sha256`)为本实现引入的安装时留档(manifest 只锚定 zip 摘要,二进制摘要留档支撑 ensure() 幂等复验,防漂移不防共谋改写,最终完整性锚定仍是 manifest sha256)。波及面=T02/T03 及 app 集成层调用 `EngineInstaller::ensure` 时,同步阻塞调用应放 spawn_blocking。
- 测试域 unsafe 声明(2026-10-09 组装前补录):`installer.rs` 测试模块含 2 处 `unsafe { std::env::set_var / remove_var }`(ENGINE_ROOT_ENV 覆盖路径测试,现场均带 SAFETY 注释)。理由:Rust 2024 edition 将环境变量变更标为 unsafe 且 std 无安全替代;范围仅测试进程单线程用例,其余测试不读该变量;生产代码零 unsafe。依据作业红线「需要 unsafe 先提 ADR」,本节即其声明;T02/T03 如需同类测试手法引用本节,不再重复立 ADR。
