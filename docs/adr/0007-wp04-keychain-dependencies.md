# ADR-0007 WP04 keychain 依赖集(keyring 2.3.3;getrandom 0.2 非 unix 分支)

- 状态: 接受 | 日期: 2026-10-10 | 负责人: @partiverse
- 背景: M1-WP04-T01(config 加密主密钥的 keychain 托管)。卡内候选池=keyring crate,要求实测其 linux 后端系统依赖(拉 libsecret 系系统包则评估纯 Rust 替代并给理由)、license 逐个读 registry Cargo.toml 实测、deny 全节绿。硬约束:deny.toml `multiple-versions="deny"` 全目标 union 不可改(作业红线)、workspace 禁 unsafe、CI 必需门禁=ubuntu-latest `gates (linux)`(ci.yml 实查,win/mac smoke 为 continue-on-error)。
- 决策: partiverse-core 新增直接依赖 **keyring 2.3.3**(`default-features = false`,features=`platform-windows`+`platform-macos`+`linux-default-keyutils`,license=MIT OR Apache-2.0,registry Cargo.toml 实测)——单 API 覆盖三平台原生存储:linux=内核 keyutils(keyutils 条目 description=`keyring-rs:<account>@<service>`,KeyType::user;**不跨重启**,上游 keyutils.rs「Persistence」=「secure cache」口径,重启后 KeyMissing→上层显式重新供给);windows=Credential Manager(依赖 windows-sys ^0.52,与树内 ring 同版零新增版本);macos=Keychain(security-framework ^2.6)。另在非 unix 目标新增 **getrandom 0.2.17**(license MIT OR Apache-2.0;树内既有版本=ring 传递依赖,零新增版本;主密钥 CSPRNG 的 windows/mac 分支,unix 仍按 ADR-0005 先例 std 读 /dev/urandom)。`cargo tree --workspace --target all --duplicate` 实测零重复;`cargo deny check` 四节全绿(advisories 经代理 7897 拉库实测);linux 后端零系统包、零 D-Bus 守护进程依赖、零 unsafe。
- 理由(候选池逐项实测证据,全部本机复现,非记忆):
  1. **keyring 4.2.0(最新线)不可用**:不启 v1/cli 特性时 compile_error(其 src/lib.rs);启 v1 默认集则把 zbus/secret-service 5.2 树拉进 union → getrandom 0.2.17/0.4.3、syn 2.0.119/3.0.6、windows-sys 0.52.0/0.61.2 三族重复,cargo deny bans 红(deny.toml 红线不可改白名单)。
  2. **纯 Rust 替代(zbus 系 secret-service)评估=否决**:keyring 4.2 的 `zbus-secret-service-keyring-store` 及直用 secret-service crate 同属 zbus 5.19 树(async-io/async-signal/polling/uds_windows),同样触发上述三族重复——纯 Rust 与 deny 全绿在本仓不可兼得。
  3. **dbus 系(libdbus 同步后端)评估=否决**:keyring 3.x `sync-secret-service` 与 4.2 `dbus-secret-service` 均经 libdbus-sys 链系统 libdbus;GitHub runner-images Ubuntu2404-Readme 实查 **libdbus-1-dev 不在预装清单**(libsecret-1-dev 亦缺),必需门禁 gates(linux) 必红,而 ci.yml 不在本卡允许文件清单。
  4. **windows 后端三路否决**:4.x `windows-native` 存储(windows-sys 0.61 vs ring 0.52 → deny 红);`windows` crate 0.62 直连(windows-implement 0.60.2 钉 syn ^2.0,与 serde_derive 1.0.229 的 syn ^3 语义不兼容 → syn 双版本 deny 红;rsproxy index 实查 windows-implement 全版本含 0.100.0 均 syn ^2,serde_derive ≤1.0.228 才用 syn 2);winapi/windows-rs 裸 FFI(调用点需 unsafe,触 workspace 禁 unsafe 红线,ADR-0005 libc 否决同款)。keyring 2.3.3 的 windows 后端=windows-sys ^0.52 与 ring 同版,union 零新增。
  5. **serde 降级对齐(1.0.229→1.0.228)未采用**:仅为 `windows` crate 直连路线服务;keyring 2.3.3 路线使 serde 零改动,不引入工作区级回归面。
  6. **keyring 2.3.3 的代价**:2.x 线已被上游 3.x/4.x 取代(升级跟随义务登记);其 CLI 伴生依赖(clap/rpassword/whoami/rand,manifest 非 optional)入 union——实测与既有树零重复、deny 全绿,接受。
- 影响: 正向=零系统包/零 unsafe/deny 全绿/单 API 三平台,linux 后端 headless 可真实测试(本机内核 keyring 集成实测通过;keyctl 取密脚本=config/ 模板实测可用;Windows ps1 模板**待 Owner 实测**)。代价=①linux 重启后密钥丢失为显式 `KeyMissing` 错误路径(上层重新供给,重新生成则旧 config 失效——卡内已声明的显式语义);②上游版本升级时需复跑 deny 全节与重复版本检查。升级路径:zbus/windows 绑定栈版本收敛(syn 3 化、windows-sys 对齐)后可评估回归 secret-service/windows-native 后端。
