# Partiverse 开发执行方案(AI 代理作业总纲)v1.0

> 状态:✅ v1.0(2026-10-08) | 母本:partisync《AI 开发执行方案》(治理继承,差异以本方案为准)
> 操作规范以根目录 [AGENTS.md](../AGENTS.md) 为准;本方案定义**工件体系、流程与门禁**。

## 1. 工件体系与目录约定

```

├── specs/P{p}-WP{nn}.md      # 工作包规格(模板 T2)

```

## 2. 流程(每个任务五步)

1. **立卡(边界界定,Owner 指令 2026-10-08:不给 AI 自由发挥空间)**:从 SPEC 分解出任务卡,**卡内必须载明四件套**——①允许触碰的文件清单(锁死);②禁止行为清单(占位桩/吞错/静默降级/硬编码端点/超范围改动/未批依赖,见 AGENTS.md);③完成定义(代码+测试+证据三件套,缺一不关账);④自由度声明(卡内未声明的实现决策一律上报 Owner,不得自行发挥;"走捷径"类判断——跳过错误分支、简化协议、mock 冒充真实——一律视为违规而非裁量);
2. **实现**:单任务单会话,≤400 行 diff,测试与实现同 PR(测试即规格);
3. **AI 对抗审查**:独立会话以"找错"立场复审(R1/R2 全审,R0 抽审 30%),**专项核查禁止行为清单**;
4. **人工终审**:Owner 合入(R2 双人全审=Owner+独立 AI);
5. **关账回填**:SPEC §3 勾选、债务台账更新、WP00 状态回填。

## 3. 门禁(M0 建立 CI 后自动执行;此前人工执行同等标准)

`cargo fmt --check` → `cargo clippy -D warnings` → `cargo test` → (前端)`lint/build` → 许可审计(`cargo deny`)→ GUI 任务附截图。红灯不合入;覆盖率只升不降。

## 4. 债务与例外台账

- 任何"先欠后补"(未实测基准/临时放行/条件触发项)必须登记于当期报告 §3,带触发条件与时钟;
- 台账跨期滚动,版本简报同步呈现;两期未动的债务升级为 R1 评审项。

## 5. 版本与简报节奏(✅ Owner 指令)

- **每完成一个小版本**(Phase 关账/V0.x 发布):提交简报(模板 T4)至 `docs/reports/` 并在会话呈现;
- Phase 关账另出正式报告(证据链:SPEC 勾选+测试证据+截图);
- Owner 待办在简报中同步催办状态。

## 6. Phase 编号与里程碑映射

- Phase 0 = 立项与设计(`P0-*`);产品里程碑进入 M 序列(M1≈V1 MVP,对照 03 开发计划 §5);
- M 序列每个 WP 须先有已批准 SPEC(铁律 1),SPEC 批准人 = Owner。

## 7. 与 partisync 的流程差异声明

1. 编号前缀:Phase 0 用 `P0-*`,其余同构;
2. CI:partisync 已有五道门禁,本仓库 M0 建立前由 AI 代行同等检查并在 PR 正文留痕;
3. 其余(十条铁律/追溯格式/原子交付/双通道审查/GUI 验收/风险分级)完全继承。

## 8. Workflow 长任务开发规划(✅Owner 指令 2026-10-08:后续开发使用 ZCode Workflow)

**单位换算**:1 任务卡 = 1 次 workflow run(≤400 行 diff 天然匹配单次预算);1 WP = 一组串/并行 runs + 1 次关账 run(回填 SPEC/台账)。

**输入契约(workflow args)**:任务卡路径 + SPEC 锚点 + 允许文件清单;上下文只喂:任务卡、指定文档路径、相关源码路径——**会话即弃铁律的 workflow 版:subagent 不获全仓上下文**。

**五段骨架(通用模板,存 docs/workflow/wp-task.template.md 占位,开工时实例化)**:
1. `preflight`:读卡→文件清单锁校验→依赖/前置任务检查→分支创建;
2. `implement`:实现 subagent(按卡内自由度声明,卡外决策→中止并上报);
3. `verify`:fmt/clippy/test + 性能预算脚本 + (GUI 任务)启动截图探针;**失败→自动修复循环 ≤2 轮→仍败停机报告,禁止绕过**(与反走捷径联动);
4. `adversarial-review`:独立 subagent 以找错立场按"禁止行为清单+边界四件套"复审;
5. `assemble`:组装 PR(测试证据/截图/SPEC 勾选草案)→**停在人类闸门**(Owner 终审/GUI 实操验收/R2 钉子),产出"待办证据清单"。

**并行边界**:同 WP 内无文件清单交集的任务可并行(如 UI 组件×核心模块);共享文件串行;跨 WP 不并行。

**闸门与失败语义**:workflow 永远停在人类闸门前,不自动合入;任何段失败产物保留(分支/日志/报告)供 Owner 检视。

## 9. 版本与发布纪律(✅D37,Owner 指令:杜绝跃升)

- SemVer;蓝图版本 ↔ 主版本号(V1→1.0 …);开发期 `0.x`;dev 构建 `0.0.0-<sha>+dev` 不入册。
- 通道:**alpha(可破坏格式)→ beta(范围功能齐+格式冻结)→ rc(只修阻断 bug,零新功能)→ stable**;越级回退规则:rc 期出非阻断问题不升版,出新功能即回退 beta。
- 升版纪律:版本号变更只发生在发布签核(Owner);普通 PR 禁碰版本;无实质功能交付不升版;签核记录随发布报告+简报归档;应用内显示通道徽标。
