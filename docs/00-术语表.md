# Partiverse 术语表(Glossary)v1.0

> 状态:**✅ 已冻结(2026-10-08 Owner 终审通过:Particle 采"内容身份级"定义,Placement 术语生效)** | 日期:2026-10-08
> 术语冻结后,代码类型名/UI 文案/文档统一执行;改名需 ADR。
> 设计原则:①产品术语与品牌同构(Particle/Node 呼应 Partiverse 与产品中文名的「粒」字根);②与底座 partisync **只映射、不撞名**;③UI 语言与引擎语言分层。

---

## 1. 核心自定义术语(产品层,Owner 提议采纳:2026-10-08)

| 术语 | 定义 | 代码类型名 | 底座(partisync)映射 |
|---|---|---|---|
| **Node(节点)** | **物理存储端**,涵盖本地与云端:本地磁盘/分区、云盘账号、NAS/S3/WebDAV/SMB 端点等。能力画像(架构 §12)以 Node 为单位 | `StorageNode` | `Volume`(本地卷)+ `Provider`(外部存储)**的统一抽象**(partisync 分两词,Partiverse 合一) |
| **Particle(粒子)** | **最小数字资产单元,以内容身份为锚**:同一内容无论存在于几个 Node,都是同一粒;文件的某个路径呈现是该 Particle 的一次驻留 | `Particle`(id 即内容哈希) | `Content`(内容身份;一粒的"内容本体") |
| **Placement(驻留)** | Particle 在某个 Node 上的一份落位(路径+元数据)。UI 叙事:"这张照片是**一粒**,存于**三个节点**" | `Placement` | `Entry`(路径条目) |
| **Chunk(块)** | 引擎内部的内容分块(CAS 原子),**不外露、不进 UI** | `Chunk` | 沿用 `Chunk` |
| **Node 画像(Profile)** | 对一个 Node 的持续能力评估结果(静态 caps + 动态健康/性能),智能策略引擎的输入 | `NodeProfile` | 对应 partisync `ProviderCaps` 思想的扩展(✅D23) |

> **定义说明(已定案 2026-10-08)**:「最小文件单元」按**内容身份级**落地(Particle=Content 锚),而非路径级文件——理由:①去重叙事自然("一粒多存");②避免与底座 Entry(路径)/Chunk(块)撞名;③与保密中文名的「粒」字根同构。Owner 终审通过,本条为定案。

## 2. 引擎术语(rclone 侧)

| 术语 | 定义 |
|---|---|
| **Engine(引擎)** | 一个 rclone rcd 守护进程实例(单实例运行,引擎槽位化预留多实例,Q5) |
| **Engine Slot(引擎槽位)** | 引擎实例的资源隔离单位(remote 命名空间/数据面端口/cache-dir 参数化);多引擎(候选 Pro 专属)即启用多槽位 |
| **Remote** | rclone 内部的一个连接配置;V1 与 Node 一一对应(backends-go 落地后 Node 经接缝映射) |
| **Job** | 引擎异步任务(rc job);Partiverse 传输任务的执行载体 |
| **Mount(挂载)** | V2:把 Node/目录挂为系统盘(rclone mount/nfsmount,✅D16) |

## 3. 平台与套件术语

| 术语 | 定义 |
|---|---|
| **Partiverse** | 本产品:聚合浏览器(唯一的消费者 GUI) |
| **PartiSync** | 底座:本地资产智能引擎(✅D19 互补协作) |
| **Pro** | 付费档(账号数/传输任务/挂载/多引擎槽位等) |
| **掌控面板** | Node 空间水位/健康/异常/去重潜力的总览界面(✅D23) |

## 4. V2+ 随 partisync 引入(沿用底座原名,不另造词)

`Space`(空间/授权单元)、`Device`(设备)、`Tag`、`Sidecar`(派生数据)、`Memory`(记忆)、`Hub`、`DupGroup`(重复组)、`E2EE 空间`。

## 5. UI 工作中文名(保密解除后随 D5 一并定稿)

Node→节点;Particle→粒子;Placement→驻留;Profile→画像;Engine→引擎。(以上为工作词,非最终文案)
